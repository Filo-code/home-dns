# A8 — Frontend Dashboard: Design

- **Status:** implemented 2026-09-14
- **Related:** [implementation-plan.md](../implementation-plan.md) §A8 · [ADR 0010](../adr/0010-frontend-hosting.md)
  (hosting) · [ADR 0005](../adr/0005-backend-dashboard.md) (backend/API this consumes, unchanged)
- **Constraints:** offline, development only. Consumes the existing A7 API against
  `MockDnsProvider`; no new backend business logic beyond the additive hosting glue in
  [ADR 0010](../adr/0010-frontend-hosting.md). No real Pi, no real Pi-hole, no network change.

## 1. Scope

A8 is the LAN-only dashboard: a React/TypeScript SPA in `dashboard/frontend/`, built on the
development machine, served by the same process as the API (ADR 0010). It adds no server-side
logic beyond static-file hosting — every number on screen comes from an existing A7 endpoint.

## 2. Modules

| Module | Role |
|---|---|
| `api/types.generated.ts` | Generated by `make gen-types` from the live `/api/openapi.json` (dev only) — never hand-written |
| `api/types.ts` | Thin aliases over the generated schema, plus `ConfigView` (hand-written — `/config` has no `response_model` to generate from) and query-param interfaces |
| `api/client.ts` | `apiFetch<T>()` — stateless, typed, same-origin, throws `ApiError` |
| `api/useApiClient.ts` | The stateful policy: 401 → clear session + redirect; CSRF-403 → refresh once, retry once |
| `router.tsx` | Hand-written route table (`useSyncExternalStore` + `history.pushState`), `<Link>`, path helpers |
| `context/AuthContext.tsx` | Context + reducer: `{status, username, role, csrfToken}`, nothing persisted |
| `hooks/usePolling.ts` | Poll-with-backoff-free interval, paused on `document.hidden`, never overlaps requests |
| `components/` | `Nav`, `Card`, `Table`, `StatusBadge`, `LoadingState`/`EmptyState`/`ErrorState`, `charts/{Sparkline,LineChart,BarGauge}` |
| `pages/` | `Login`, `Overview`, `Devices`, `DeviceDetail`, `Security`, `System`, `Alerts`, `QueryLog` |
| `lib/format.ts`, `lib/severity.ts` | Italian formatting and status→severity/label mapping, shared by every page |
| `styles/{tokens,base,responsive}.css` | Custom-property tokens, mobile-first layout, phone/tablet/desktop breakpoints |

## 3. Dependencies

Runtime: unchanged (`react`, `react-dom` only). Dev: `openapi-typescript` — but isolated in
`scripts/codegen/` with its own `package.json`/lockfile, **not** in `dashboard/frontend/`, because
it needs the classic TypeScript compiler API and has no published version compatible with
TypeScript 7 (which the frontend itself is pinned to) — see technical-debt register. No router,
HTTP client, state, or chart library was added.

## 4. Routing

Routes: `/`, `/devices`, `/devices/:id`, `/security`, `/system`, `/alerts`, `/queries` (admin-only
nav entry), `/login`. `navigate()` is a plain function usable outside React (the 401 handler calls
it directly). Direct-load of any route works because the backend's SPA fallback (ADR 0010) serves
`index.html` for every non-`/api` path.

## 5. Authentication flow

```
boot -> GET /auth/session  200 -> authenticated   401 -> anonymous, render Login
login -> POST /auth/login  200 -> AuthContext set, navigate(intendedPath())
                            401 -> "Credenziali non valide." (never which field)
                            429 -> "Troppi tentativi, riprova tra qualche minuto."
any request -> 401         -> clear AuthContext, navigate(/login?next=<path>)
mutation -> CSRF 403       -> GET /auth/session once, retry the mutation once, else surface it
mutation -> role 403       -> returned as-is; the page renders "Non hai i permessi..."
```

Session cookie, CSRF token and role are never written to `localStorage`/`sessionStorage`; a full
reload always re-derives them from `GET /auth/session`, which is what the server actually trusts.

## 6. Pages and role visibility

| Page | Role | Endpoints |
|---|---|---|
| Panoramica | viewer | `/overview`, `/metrics/history` |
| Dispositivi | viewer (read) / admin (rename, group via `PATCH`) | `/devices`, `/config` (groups, admin only) |
| Dettaglio dispositivo | viewer (header) / admin (Attività tab) | `/devices/{id}`, `/metrics/history`, `/devices/{id}/activity` (admin) |
| Sicurezza | viewer | `/config`, `/overview` (`blocked_by_source`), `/alerts` |
| Sistema | viewer | `/overview` (system), `/config` (storage, retention, metrics cadence) |
| Avvisi | viewer | `/alerts` |
| Registro query | **admin only**, no nav entry for viewer | `/queries` |

An admin-only fetch (device activity, query log) is **never attempted** for a viewer — checked
client-side before the request, not just refused server-side — and its data is never rendered for
a viewer even transitionally.

## 7. Charts and polling

Three hand-written SVG components (`Sparkline`, `LineChart`, `BarGauge`) — no charting library;
`/metrics/history` returns at most ~48 points, small enough for a plain `<polyline>`. Polling:
Overview/System every 60 s (matches the collector's own cadence — counters cannot change faster);
Devices/Security/Alerts every 120 s; history charts fetch once per page load / filter change, not
continuously. `usePolling` pauses while the tab is hidden and resumes on `visibilitychange`.

## 8. Security

- **CSP**, **GZip**, **SPA-fallback path-traversal guard**: [ADR 0010](../adr/0010-frontend-hosting.md).
- Domain names, hostnames and custom device names are always rendered as plain JSX text (React
  escapes by default); `dangerouslySetInnerHTML` is not used anywhere in the codebase.
- No secrets, tokens or API keys in the bundle — the API base is always a same-origin relative
  path.

## 9. Deviations from the original design pass

- **`DeviceDetail`'s `usePolling` fetcher guards against an invalid `:id`** (`Promise.reject`
  instead of calling the API) rather than letting the request fire and be discarded — found while
  writing the "no network call for an invalid id" test; hooks can't be called conditionally, so
  the guard lives inside the fetcher closure.
- **`AuthContext`'s boot effect now catches every failure**, not only 401 — a non-401 boot failure
  (e.g. the backend unreachable) used to leave the app stuck on the loading screen forever
  (an unhandled promise rejection); it now falls back to the login page, and a real login attempt
  there surfaces "Impossibile contattare il server." Found by a test, fixed in `AuthContext.tsx`.
- **`openapi-typescript` lives in `scripts/codegen/`**, not `dashboard/frontend/`, once it turned
  out to crash outright under TypeScript 7 (not just an npm peer-range warning) — see technical
  debt.

## 10. What A8 deliberately does not do

- No C2/C4/D-stage work: no real Pi-hole, no real Raspberry Pi, no DHCP/DNS/router change.
- No nginx, no Docker, no Node.js at runtime.
- No new backend business logic — `static_dir`/CSP/GZip/`--static-dir` are hosting glue only.
- No Telegram, blocklist-engine or monitoring-logic changes.
